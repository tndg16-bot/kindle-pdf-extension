# Context Engineering Fundamentals

## When to Activate
- 新規エージェントシステム設計時またはアーキテクチャ変更時
- コンテキストに関連する予期しないエージェント動作のデバッグ時
- トークンコスト削減やパフォーマンス改善のためのコンテキスト最適化時
- コンテキスト関連の設計決定のレビュー時

## Core Concepts

### コンテキストの構成要素
コンテキストは複数の異なるコンポーネントで構成される：
- **System Prompts**: エージェントの基本的な振る舞いを定義
- **Tool Definitions**: 利用可能なツールとその使用方法
- **Retrieved Documents**: RAGやファイルから取得した情報
- **Message History**: 会話の履歴
- **Tool Outputs**: ツール実行の結果

### アテンションメカニズムと制約
- コンテキストウィンドウは「トークン容量」ではなく「アテンション力学」に制約される
- コンテキスト長が増加すると予測可能な劣化パターンが発生：
  - **Lost-in-the-Middle**: 中間部分の情報が見落とされる
  - **U-shaped Attention**: 先頭と末尾に注意が集中
  - **Attention Scarcity**: アテンション資源の枯渇

### Progressive Disclosure（段階的開示）
- 起動時はスキル名と説明のみロード
- 関連タスク実行時にのみ完全なコンテンツをロード
- これにより効率的なコンテキスト使用を実現

## Guidelines

### コンテキスト品質 vs コンテキスト量
- 「より多くの情報」≠「より良い結果」
- 最小の高シグナルトークンセットを目指す
- 冗長な情報は削除またはサマリ化

### コンテキストバジェット管理
1. **優先順位付け**: 最も重要な情報を先頭に
2. **圧縮**: 長い情報は要約
3. **遅延ロード**: 必要になるまでロードしない
4. **キャッシュ**: 頻繁にアクセスする情報は保持

## Integration

このスキルは他のスキルと連携して機能：
- `multi-agent-patterns`: マルチエージェントでのコンテキスト分離
- `memory-systems`: 永続メモリとコンテキストの統合
- `context-optimization`: 具体的な最適化テクニック
