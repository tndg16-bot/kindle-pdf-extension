# ポートフォリオサイト コンセプト設計

**作成日**: 2026-01-06  
**最終更新**: 2026-01-06

---

## 🎯 サイトの目的

**「この人はどんなプロジェクトを走らせているんだろう？」という好奇心を生み出し、質問・対話につなげる。**

---

## 📊 ダッシュボードで見せるもの

### ✅ 表示するもの（技術・プロジェクト系）
- AI連携の実装（Claude Code, Codex, Ollama等）
- GitHub連携・PRワークフロー
- 開発プロジェクトの進捗
- コード・システムの構築状況
- ツール統合の取り組み

### ❌ 表示しないもの（ビジネス数値系）
- 営業数値
- 売上・収益
- クライアント数
- その他の機密ビジネスデータ

---

## 💡 期待するユーザー行動

1. **サイト訪問** → プロジェクト進捗を見る
2. **興味・好奇心** → 「このプロジェクトって何？」「どういう意味があるの？」
3. **質問・対話** → オフライン/オンライン（メールなど）で問い合わせ
4. **関係構築** → セッション予約や協業につながる

---

## 🔧 ダッシュボード設計指針

### データソース
- `本山貴裕/やりたいことリスト.md` から自動取得
- GitHub APIで最新状態を反映

### 表示項目
| セクション | 内容 |
|-----------|------|
| **プロジェクト進捗** | 合計/完了/進行中/未着手のカウント |
| **最新アクティビティ** | 最近の開発マイルストーン |
| **技術スタック** | 使用技術・ツール連携状況 |

### 更新タイミング
- やりたいことリスト.md を更新 → ダッシュボードに自動反映
- 重要な技術的マイルストーンは「開発の歩み」に追記

---

## 📝 タスク記載のルール

### 記載する例
```markdown
- [x] GitHub CLI連携 (v2.83.2)
- [x] AIチームオーケストレーション実装
- [/] ポートフォリオ Phase 10: 新ページ実装
- [ ] Claude Code Webとの並列ワークフロー確立
```

### 記載しない例
```markdown
- [ ] 今月の営業目標: 〇〇件
- [ ] クライアントA様への提案
- [ ] 売上目標達成度: 80%
```

---

## 🎨 デザイン原則

1. **好奇心を刺激する**: 専門用語を恐れず使う（質問のきっかけになる）
2. **進捗を可視化**: 「動いている感」を出す（停滞感を与えない）
3. **問い合わせへ誘導**: 「詳しく聞きたい」と思わせる余白を残す
4. **信頼性を担保**: 具体的な数字・日付・ツール名で裏付ける
