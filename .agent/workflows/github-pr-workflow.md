# GitHub PR ワークフロー（サブエージェント向け）

**作成日**: 2026-01-06  
**目的**: サブエージェント（Codex/Claude Code）がGitHub経由でユーザーと非同期コミュニケーションを行うためのガイド

---

## 📋 基本フロー

```
1. ブランチ作成 → 2. 実装 → 3. Commit → 4. PR作成 → 5. 質問はPRコメントへ → 6. ユーザー返答待ち → 7. 続行 → 8. マージ
```

---

## 🔧 コマンドリファレンス

### 1. ブランチ作成
```bash
git checkout -b feature/[タスク名]
# 例: git checkout -b feature/about-page
```

### 2. 変更をcommit
```bash
git add .
git commit -m "feat: [説明]"
# 例: git commit -m "feat: Aboutページを仕様書に従って更新"
```

### 3. プッシュ
```bash
git push -u origin feature/[タスク名]
```

### 4. PR作成
```bash
gh pr create --title "[タスク名]" --body "## 概要
[変更の概要]

## 仕様書
- specs/[仕様書名].md

## 確認事項
- [ ] ローカルで動作確認済み
- [ ] デザインガイドに準拠"
```

### 5. 質問がある場合（PRコメント）
```bash
gh pr comment [PR番号] --body "## ❓ 質問
[質問内容]

## 選択肢
- A: [オプションA]
- B: [オプションB]

@tndg16-bot ご確認お願いします"
```

### 6. ユーザー返答確認
```bash
gh pr view [PR番号] --comments
```

### 7. マージ（ユーザー承認後）
```bash
gh pr merge [PR番号] --squash --delete-branch
```

---

## 📝 PRテンプレート

```markdown
## 概要
このPRは [仕様書名] に従って [ページ名] を実装/更新します。

## 変更内容
- [ ] [変更1]
- [ ] [変更2]
- [ ] [変更3]

## 仕様書リンク
- `specs/[仕様書名].md`

## スクリーンショット
（該当する場合）

## 質問・確認事項
（なければ「なし」）

## チェックリスト
- [ ] ローカル動作確認済み (localhost:3001)
- [ ] エラーなし
- [ ] デザインガイド準拠
```

---

## ⚠️ 注意事項

1. **必ずブランチで作業**: `main` に直接pushしない
2. **質問は即時ではなくPRコメントへ**: ユーザーは非同期で確認する
3. **マージはユーザー承認後**: `gh pr merge` は承認を待ってから
4. **通知を活用**: `@tndg16-bot` でメンションすると通知が飛ぶ

## 🏷️ ラベル運用

| ラベル | 意味 |
|--------|------|
| `portfolio` | ポートフォリオ関連 |
| `question` | ユーザーへの質問あり |
| `ready-for-review` | レビュー準備完了 |
| `wip` | 作業中 |

```bash
# ラベル追加
gh pr edit [PR番号] --add-label "question"
```
