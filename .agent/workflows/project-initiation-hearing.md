# 📝 Workflow: Project Initiation Hearing

このワークフローは、新しいプロジェクトや大きな機能の追加が始まる際に、必ず **Leo(PM)** が主導して実行する「不変の儀式」です。

## 🔄 Steps

### 1. 専門家の招集 (Assembly)
Leo, Mia, Kai の3名が本山さんの前に並び、挨拶をします。

### 2. 核心のヒアリング (Core Inquiry)
以下の項目について、本山さんの今の「直感」と言葉を伺います。

- **今回のテーマ・感情**: どのような「手触り」や「感情」をユーザーに残したいか？
- **最優先事項**: 機能の完成か、ビジュアルの美しさか、それとも特定のメッセージの伝達か？
- **不変の制約 (Immutable Elements)**: 絶対に変えてほしくない色、形、ルールはあるか？

### 3. ハーネスの初期化 (Harness Initialization)
ヒアリング結果に基づき、今回のプロジェクト限定の `Immutable Harness` を定義し、`.claude/memories/[project-name].md` に保存します。

### 4. 実行計画の提示 (Plan Presentation)
Leoが全体のタスクを分解し、本山さんに「学習ガイド付きのチェックリスト」を提示して承認を得ます。

---

## 💡 Learning Points for Motoyama-san
- **ヒアリング (Discovery)**: 開発を始める前に「何を、なぜ作るのか」を言語化する、最も重要な上流工程のこと。
- **不変の制約 (Immutable)**: デザインシステムやアーキテクチャの一貫性を守るための「動かせない石」のこと。
